# Code of Conduct

## Our commitment

GeDefense Retail is a defensive security project for critical store infrastructure. We want
contributors and users to participate in a professional, respectful and safety-conscious
environment, regardless of experience level, background or employer.

## Expected behavior

- Be respectful and constructive in issues, pull requests and discussions.
- Assume good intent, but challenge technical claims with evidence.
- Respect the project's safety boundaries: no OT write paths in monitoring, no active scanning of
  production devices, no compliance claims without proof.
- Protect sensitive information: never post credentials, tokens, private keys, customer data or
  details of live OT environments. Use synthetic examples.
- Give credit for work and ideas; accept feedback gracefully.

## Unacceptable behavior

- Harassment, discrimination, threats, personal attacks or sustained disruption.
- Publishing someone's private information without permission.
- Sharing secrets, real plant data or vulnerabilities publicly before coordinated disclosure.
- Encouraging or performing destructive testing against systems you do not own or are not
  authorized to test.
- Misrepresenting the project's security properties, certifications or test results.
- Spam, advertising or unrelated self-promotion.

## Scope

This code applies to project repositories, issues, pull requests, discussions and any project
communication channel. It also applies when representing the project in public.

## Reporting

For conduct concerns, contact the maintainers through the repository's private contact options or a
GitHub security advisory if the matter is sensitive. Reports are handled confidentially and in good
faith. Do not use public issues to report personal or security-sensitive matters.

For **security vulnerabilities**, follow [SECURITY.md](SECURITY.md) — not this document.

## Enforcement

Maintainers may edit or remove contributions, close discussions or temporarily/permanently restrict
participation when this code is violated. Enforcement decisions aim to be proportionate, documented
and focused on keeping the project safe and usable.
